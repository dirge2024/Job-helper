# 求职助手改版实施方案

状态：执行中。产品需求以 `dashboard-redesign-requirements.md` 为准。

## 执行规则

- 每个阶段完成后，运行相应检查并向用户确认，再进入下一阶段。
- 不删除已存在的业务能力；迁移或合并入口时保留数据和操作路径。
- 不提交 API Key、WebDAV 用户名密码、完整备份、真实简历、投递记录、浏览器配置或任何用户数据。
- 推送前执行 `git diff --check`、敏感信息扫描、测试和待提交文件清单审查。
- 每个通过验收的阶段单独提交；仅在用户确认阶段结果后推送到 GitHub。

## 阶段 0：源码与安全基线

目标：定位浏览器正在加载的 dashboard 页面源码，并确认仓库、分支、远程仓库及忽略规则。

验收：确认实际扩展根目录与当前仓库的关系；补齐敏感文件忽略规则；不修改业务代码。

## 阶段 1：统一应用外壳

目标：将页面改为“求职助手”的单层横向导航。

范围：投递管理、面试日程、面经复盘、简历资料库、数据洞察、备份与同步六个同级入口；统一暖白、浅灰绿、鼠尾草绿视觉规范。

验收：六个入口均可切换；旧能力有对应入口；桌面与窄屏布局正常。

## 阶段 2：投递管理

目标：实现全宽投递列表及统一工具栏。

范围：截图识别、导入、导出备份、新增投递、搜索、排序、进度筛选；表格保留城市、投递日期、编辑、删除；进度使用彩色自定义选择器。

验收：九种进度可切换且颜色正确；列表字段与原数据兼容；编辑与删除可用。

完成记录（2026-09-05）：

- 已在新版工作台实现全宽投递列表、搜索、进度筛选、排序、CSV 导入导出、新增、编辑和删除。
- 已实现九种进度及颜色：已投递、测评、笔试、一面、二面、三面、HR 面、Offer、中止；中止使用红色。
- 旧数据状态 `待投递`、`已笔试`、`面试中`、`offer`、`终止` 会自动归一化为新状态，不丢弃历史记录。
- 当前仓库没有独立“截图识别并创建投递记录”能力；原有招聘网页识别与 AI 框选填充仍保留在悬浮助手中，未伪造无效按钮。

## 阶段 3：自动面试日程

目标：从进度变更自动生成面试日程。

范围：进度变为一面、二面、三面、HR 面时弹出日期时间选择；默认线上；暂不安排只保存进度；月历支持选择月份、改期与取消。

验收：日历按真实月份渲染；四种面试阶段均可自动入日程；关联更新不会产生重复记录。

完成记录（2026-09-05）：

- 投递记录新增可选的多轮面试日程字段；一面、二面、三面、HR 面可同时保留，并随完整 JSON 备份和同步保存。
- 在投递列表直接修改为面试阶段时弹出安排窗口；仅填写日期时间，线上为默认，不提供地点或会议链接字段。
- “暂不安排”只更新进度；“保存并加入日程”创建或更新对应轮次的日程。
- 月历使用原生月份选择与前后月按钮，根据真实起始星期和当月天数生成格子；日程可改期或取消，取消会同步移除投递记录中的对应日程。

## 阶段 4：面经复盘

目标：保留现有复盘编辑体验并接入自动记录。

范围：左侧编辑、右侧列表、搜索、筛选、添加面经；自动生成待复盘记录；AI 总结和保存复盘保持在编辑区底部。

验收：手动补录和自动生成均可用；记录正确关联公司、岗位、轮次和日程。

## 阶段 5：资料、洞察、备份与悬浮助手

目标：整理剩余页面并统一视觉。

范围：多简历资料库、可选 AI 配置、独立数据洞察、导入导出/WebDAV、悬浮助手绿色主题。

验收：未配置 AI 时核心流程可用；原有备份、同步和悬浮助手能力保留。

## 阶段 6：验证与发布

目标：完成回归、安全检查、提交与推送。

范围：测试、构建、Chrome/Edge 扩展加载验证、敏感信息扫描、Git 提交和 GitHub 推送。

验收：所有检查通过；提交仅包含源码、测试、文档和必要静态资源；远程仓库推送成功。
